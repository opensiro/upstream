**PATCH · 2026-11-20.** Documentation-only, nonbinding clarification of the published v0.18.0 Roadmap protocol. No new review obligation, scoring model, feature admission rule or native implementation.

## Recommendation

Prefer a proposed function-specific `Sx=C` constructor that is **native-specific** to the original harness: describe concrete shipped first-party components and supported interfaces, the particular operating scenario and authority boundary, the smallest missing integration, and how a real subsequent native action and returned feedback would complete the intended function. Reuse native mechanisms instead of grafting a generic VSM supervisor, reviewer or adapter with only renamed symbols. If the same design would read unchanged for many unrelated harnesses, consider tightening the source-native path rather than introducing a generic abstraction.

This is **advisory only**: a generalizable construction is not automatically rejected, and neither specificity nor measured product benefit is a new GO/NO_GO criterion. The v0.18.0 constructibility decision contract, source/authority preflights, accepted Index ownership, maintainer-owned adoption, existing validators and third-party publication consent remain unchanged.

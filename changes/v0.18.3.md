# v0.18.3 — Exact GitHub Issue payload and canonical case template repair

**PATCH · 2026-11-22.** Owner-approved repair to the v0.18.2 publication-template enforcement, not a new Roadmap admission criterion or an implementation mandate.

## Defects fixed

1. A case could pass four-file Human/AI template checks, yet an agent could manually rewrite an entirely different **public fork Issue** for GitHub approval. The OpenCode example replaced the mandatory eight Human sections with free-form Purpose / technical sections. The new `scripts/validate_public_issue_payload.py` renders fork title/body directly from the verified Human case and rejects all non-deterministic edits or missing sections.
2. An externally presented original-maintainer Roadmap Issue lacked a last-mile template gate. The same command now checks the exact external issue against `templates/EXTERNAL_ARCHITECTURE_ISSUE.md`, including all six historical states, provenance, plain-language keys, disclaimers and distinct owner consent.
3. The already merged main-branch [PR #92](https://github.com/opensiro/upstream/pull/92) tightens template checks on **every materially revised canonical fork-local case**, not only future external PRs. Its case validation change is consolidated into this patch since the last verified published v0.18.2 release.

## Execution and validation

- Current accepted historical Index assessment, current original default HEAD, verified fork metadata SHA and owner control are separate preconditions. An original Issue older than 30 days triggers deeper first-party review under [pilot #93](https://github.com/opensiro/upstream/issues/93).
- Render/check public fork Issue from the exact case snapshot: `python3 scripts/validate_public_issue_payload.py --kind fork --case-dir CASE --repo OWNER/REPO --case-ref SHA --source-head HEAD --title-file TITLE --body-file BODY --render-fork`; omit `--render-fork` to recheck the exact POST bytes. Original maintainer-facing drafts use `--kind original` with their separate template.
- A PASS is **only structural**. No native test, effective C ownership, measured benefit, maintainer endorsement, permission to publish, delegated S5 autonomy or current reassessment is implied. Require new exact consent on material changes.
- Verification: complete Upstream unit suite and current OpenCode fork-local Roadmap/case-payload checks must pass in the final reviewed PR before merge. A VERSION change alone is not a release or tag.

## Protocol changes

1. **Capability-first research:** before extensive bug/SDK/reliability probes, record the **new user task, action/output, current native alternative, source-backed demand or honest uncertainty, bounded value proxy and negative/compatibility control**. See [capability-first research](../docs/CAPABILITY_FIRST_RESEARCH.md).
2. **Feature versus repair:** `MINOR_FEATURE`/`MAJOR_FEATURE` denotes an independently useful new workflow; `BUG_FIX`/reliability and existing/duplicate capability are distinct prose categories. A mock error, SDK incompatibility or retry guard is not automatically new product functionality.
3. **Decisive product-native test:** prioritize a matched original-vs-new workflow fixture or exact maintainer-owned design decision instead of endless defect checks. Unresolved feature demand/contract remains `OPPORTUNITY_RESEARCH_PENDING` with precise owner and next evidence.
4. **Honest VSM attribution:** Index-first capability predictions must be frozen before fresh source/issues; maintainer-driven ideas stay `ASSESSMENT_INFORMED` or `GENERAL_UPSTREAM`, not retrospectively derived from Index.
5. **No relaxation of gates:** the previous S1/S2/S3/S3*/S4/S5 sweep, all `need/mechanism/counterfactual/scope = PASS`, independent deterministic strict-derived runner, source rights and external publication stages still apply. Ordinary supported repairs can proceed in their existing lane without claiming feature progress.

# v0.18.2 — Fail-closed Roadmap publication-template preflight

**PATCH · 2026-11-20.** Requested protocol patch formalizing the already merged fix to Human/AI template validation. The last verified published tag before preparation was v0.18.0; the v0.18.1 native-specific advisory package was integrated on main without evidence of a separate published tag.

## Defect fixed

The older roadmap receipt structural validator could report PASS for matching Human/AI decision status and six-function data even when a Human issue did not follow the required eight-section template or an AI companion did not follow the six-section template. Gas Town Wave 4 was a reproducible example: neither full template was present, yet the source receipt consistency check passed.

Merged [PR #90](https://github.com/opensiro/upstream/pull/90) implements mandatory source-only template checking before an external PR that arises from or relies on an existing Roadmap case. Its new validator is [scripts/validate_roadmap_publication.py](../scripts/validate_roadmap_publication.py).

- Read back a verified actual fork metadata commit, then require README.md, issue.md, constructor-sufficiency.md and roadmap.md at one stable case directory.
- Require full current eight-section Human and six-section AI structures, meaningful filled template fields, accepted historical six-function states and provenance, selected function, native Track A/B, priorities, status and links. Reject inconsistent, missing and unfilled artifacts with PR_BLOCKED_NO_WRITE.
- Keep the existing roadmap receipt validator for ordinary plan-only and legacy cases. Code-only Upgrades without Roadmap evidence retain their existing contribution record, five-link review and publication validator; PRs that cite both routes must satisfy both.
- Checks are structural, and do not supersede native testing, original source review, owner control, consent, or third-party maintainer authority.

## Previously integrated changes consolidated

- **v0.18.1 advisory:** Recommend harness-native, source-pinned first-party construction descriptions instead of generic relabeled controllers. This is nonbinding and does not change GO/NO_GO.
- **Roadmap reporting hygiene:** Avoid per-run Upstream status-only PRs and separate Markdown reports; detailed durable case records stay on each verified matching fork metadata branch. Existing issue coordination and a single optional supplementary navigation remain permitted.

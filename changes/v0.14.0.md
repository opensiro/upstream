# v0.14.0 — Capability-first upstream upgrade

**Prospective MINOR, 2026-11-16.**

## New upgrade workflow

- `upstream upgrade` selects a concrete new operator/user action, decision or output; compare existing original-version alternatives, source-native baseline, a bounded benefit proxy and falsifiable VSM mechanism *before* patch work.
- `upstream upgrade OWNER/REPO` or `upstream upgrade <contribution-id>` continues current source/fork-local improvement identity instead of creating a batch or new issue.
- `upstream upgrade batch N` retains explicitly requested **N distinct original source harnesses**, each with reasoned S1/S2/S3/S3*/S4/S5 dispositions, but pursues deep native tests for actual promising opportunities, not six unrelated forced fixes. Report a shortfall rather than filling with duplicates.
- `upstream batch [N]` remains a separate technical/repair route. A fix is a useful `REPAIR_ONLY` result, not automatically a new capability or causal VSM discovery.

## Evidence and gates retained

Explicit actor/trigger/new output, source-owned user demand or honestly unproven prediction, existing alternative, first-party native before/after under a negative/compatibility control and `need / mechanism / counterfactual / scope` gates. `ASSESSMENT_DERIVED` requires pre-existing dated pinned Index-first chronology; source-first work stays `ASSESSMENT_INFORMED` or `GENERAL_UPSTREAM`. Retain unknown/negative outcomes, no PR quota and no product-deployment claims from merge alone.

Read real fork `parent.full_name`, branch HEAD and `owner_control` before any effectful step. `DORMANT / PAUSE` does not automatically resume work. External public issue/comment/PR/proposal requires exact current-conversation consent; this change grants no new CLA/DCO rights, daemon, executor, scheduler, fork-writing authority or new metric.

## Compatibility and implementation status

Legacy `upstream-old` frozen records remain original, with their historical procedure; do not rewrite them. Current `.opensiro/` schema introduced with v0.13.0 remains unchanged. These `upstream upgrade` forms are **conversational routes**, not installed shell commands or autonomous batch execution. The existing read-only aggregator continues to supply source-dated PR states. No automatic release or tag is implied by this package.

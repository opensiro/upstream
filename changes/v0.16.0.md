# v0.16.0 — License and contributor formalities before popularity; human access inbox

**Prospective MINOR; 2026-11-16.** This is a new ordering/triage obligation for future source selection. It does not rewrite already integrated v0.15.0 or historical v0.8–v0.11 native evidence.

## Pre-selection contract

1. Resolve original owner/repo and current source SHA. **Before contributor-popularity ranking** inspect actual license text and scope, contributor rules, CLA/DCO/sign-off, issue/assignment workflow, and current public source access evidence. Prefer the existing verified, GET-only `upstream-old` candidate intake preflight (or equivalent first-party readback); do not build a new universal runner.
2. Split candidate results into `SCREENABLE_READ_ONLY`, `HUMAN_GATE_PENDING`, and `INSUFFICIENT_EVIDENCE` narrative dispositions. They do **not** alter fork-local JSON enums. Readable license text is `LICENSE_REVIEW_REQUIRED` until applicable legal rights are independently established; a missing root license is not an automatic judgment on all subdirectories or alternative licenses. API errors are not license absence.
3. Rank only screenable, permitted read-only candidates by unique contributor count and the existing uniform/linear selection policy. Explicit project choice skips popularity rank but not license and authority checks.
4. Defer questions about source/fork/provider availability, personal CLA/DCO assent, rights and contributor requirements to the human. When a *concrete, deduplicated human decision* requires durable tracking, use the new internal **Human gate — license, formalities & availability** GitHub Issue form, retaining first-party evidence and exact decision scope. Do not create an issue per screened row or batch; one issue is an inbox pointer, not a duplicate contribution ledger or permission grant.

## Preserved

Chat-native batch reports, original-source authority, independent source-native validation, four qualification gates, existing verified forks and `.opensiro/`, exact external-publication consent and the owner `DORMANT/PAUSE/STOP` control. No third-party write, fork edit, new scheduler, public comment, automatic CLA assent, new metric or standalone legal grader is introduced. This issue form is not a new S1/S2/S3*/S4/S5 control plane.

## Implementation and limits

One template + current protocol/operator docs + version/change package + documentation consistency tests. The old read-only preflight has its own historical tests and remains in its original repository. A template alone does not make human decisions, grant account access, or automatically post human-gate issues. No tag or GitHub Release is implied by this package.

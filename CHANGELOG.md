## Unreleased
**C-first capability roadmap + approved v2 fork Issue template (unreleased):** Roadmap research now explicitly seeks a minimal, user-justified first-party `C` construction path for relevant functions without confirmed `C` or `A`. Existing `A`/`A(P)` and `C`/`C(P)` are exempt from mandatory C targets; `P` rights remain legitimate. Distinguish P0 C sufficiency, P1 enabling dependencies and P2 optional independent modes. Adopt the eight-section evidence and target-matrix fork Issue template v2; require a source-native coverage/acceptance and no-grade gate. No automatic implementation, Index write, version bump or external publication.

**Generic fork-local roadmap Issue template (unreleased):** Add a concise, project-neutral, evidence-first Issue skeleton for Opensiro's own verified working forks. It ties the user's outcome to existing original code/Issues/PRs, optional VSM-derived priorities, acceptance, native alternatives, paired cost measurement and a conditional handoff, while keeping case artifacts on `opensiro/meta`. This is distinct from the existing external architecture Issue template and authorizes no public Issue, implementation or new grade. No named-fork research edited, version bump or Release.

**Fork Issue → issue-local evidence → separately consented original Issue (unreleased):** Source-pinned case roadmaps, construction contracts, drafts and results belong in the verified matching fork's `opensiro/meta:.opensiro/issues/<case-id>/`. Public fork GitHub Issue creation and external original Issue publication each require their own exact owner approval; dedupe original issues and link rather than manufacture duplicates. Do not claim GitHub cross-owner native transfer, mirror comments/reactions, or auto-close internal Issues. Named Paperclip and Browser Harness case examples migrated to their forks; central Upstream retains generic methods and source-neutral validator fixtures. No product code, Index grade, version bump or Release.

**Roadmap-to-Upgrade execution continuity (unreleased):** Keep `upstream roadmap` strictly plan-only when that is the owner's request, but route a subsequent explicit instruction to implement the accepted `C` constructor through the existing single-original full-cycle Upgrade. Require verified source/overlap and capability delta, actual first-party vertical-slice code and native positive/negative tests, a verified fork product branch plus schema-v2 meta evidence, and exact draft fork-local PR handoff. The existing separate public fork-local and external-publication consent gates are unchanged; no automatic PR, Index grade, protocol version bump or Release.

**Roadmap C-target construction/acceptance contract (unreleased):** Require a function-specific first-party constructor interface, independently composable agent decision ownership, authorized return to subsequent operation, boundary reachability and native positive/negative acceptance cases before describing a roadmap target `C` as implementable. Add a Paperclip S4=C proposal with ten falsifiable test scenarios, tied to the accepted November Index reassessment; no first-party Paperclip code, external publication, automatic grade change, SemVer bump or Release.

**Roadmap assessment-freshness advisory (unreleased):** If the most recent successful Index semantic review/check is more than 30 calendar days old, recommend an Index-owned source-pinned re-assessment before confident architecture-gap claims. Material product change can trigger an earlier recommendation. Preserve the old accepted vector until Index admission; allow explicitly provisional read-only roadmaps while the re-assessment is pending. No automatic regrade, periodic Index mandate, new assessment controller, third-party publication, SemVer bump or Release.

**Architecture-first Upstream roadmap (unreleased):** Add a named-source, plan-only contribution route for mapping assessment, native issues/PRs and proposed composable capabilities, with independent options for product code, Profile/Skills feedback and domain-specific forks. VSM-standardization and development-cost benefit remain hypotheses; no automatic assessment regrade, agent autonomy, new fork metadata enum, third-party publication, SemVer bump or Release.

**Autonomy preflight before Upstream Upgrade source ranking (unreleased):** Following the existing license/formalities read-only preflight, check whether a non-core agent-assisted contribution can actually reach a permitted PR: contributor path, issue/design approval, CLA/DCO and human-only attestations, AI disclosure, native test availability and review requirements. Report source-backed direct/conditional/issue-only/unknown paths without inventing permission or a new fork state; prefer viable autonomous PR paths among function-credible candidates before deeper feature/popularity ranking while preserving one-harness lock and exact public-publication consent.

**Function-scoped evidence-first Upgrade (unreleased):** Explicit `S1`–`S5` operator qualifiers now narrow bounded read-only source preselection to an independently grounded function-specific user need before the one-harness lock. After selection, research stays in the same original and requested function, with decisive owner, actual decision/feedback rights, enforcement versus ownership and return-to-operation closure checked against the normative Profile. S5 requires legitimate identity/ultimate-policy decision closure, not a static policy, guardrail, browser permission or routine human approval. Existing overlap, material capability-delta, native tests, classification, fork-local review and exact external-publication consent remain independent gates. Clarifying Unreleased contract, without new JSON enums, Index reassessment, version bump or release.

**bb PAUSE-safe issue-watch route (unreleased):** Add a validated transient read-only descriptor for the get-bb/bb archive-safety maintainer decision, without modifying paused fork metadata or creating a second ledger. Enable scheduled read-only observations for bb plus registered Upstream issue watches, retaining separate exact owner gates and fork-scoped opt-in credentials for any metadata-event writes. No personal notification delivery or automatic external PR.

**Dashboard generated-data delivery and public issue watch:** CI publishes validated `docs/activity.*` and `docs/ACTIVITY.md` directly to `main` using a non-force, file-scoped commit instead of recurring PRs. External issue checks run every six hours with a public read-only token and produce no false durable alerts; optional fork-local event/cursor writes continue to require explicit manual opt-in and fork-scoped credentials. No third-party PR publication authority is added.
**Resumable Upgrade context handoff (unreleased):** Source-first five-link handoff generation from the existing fork-local schema v2 contribution, pinned metadata/product refs and current owner controls. A forgotten link or lost chat context cannot silently inherit publication approval; explicitly record a later publication STOP, run current-body preview/new structural link checks and preserve the true NOT_CREATED fork-review state. Offline generator and regressions do not create third-party PRs or provide independent GitHub readback/authorization.


**Source-linked issue decision watching (unreleased, #22):** Optional per-contribution watch of original issue comments/maintainer replies, selected labels and close/reopen state. Source-anchor validation, bounded readback, meaningful-change classification, durable fingerprint dedup and non-force fork-local CAS event writes; an opt-in read-only/manual or scheduled GitHub Actions workflow, with separate fork-scoped write token and no automatic third-party PR publication. Historic v1/v2 metadata and PR counters remain intact.


**Material capability-delta gate before Upgrade coding (unreleased):** Require a source-backed actor/task/outcome, pinned baseline and best workaround, end-to-end measurable new result, VSM mechanism and explicit materiality disposition before qualifying or implementing a feature. Passing native tests, new knobs or VSM relevance alone do not justify public Upgrade PR proposals; failed/uncertain hypotheses remain within the same selected harness. Clarify that `VSM derived & informed only` is a strict filter over existing origin types, not a new enum or causal shortcut.

**Dashboard PR reuse under restricted Actions permissions (unreleased):** Reuse an existing review PR by comparing and updating only its dedicated branch with a branch-SHA lease, without a repeated PR-creation API request. A new PR still respects the repository setting and fails closed if Actions creation is disabled; incomplete aggregate scans now print actionable warnings instead of an opaque exit code.

**Mandatory contribution origin classification (unreleased):** Newly authored fork-local improvements use contribution schema v2 with a source-backed `contribution_type`, rationale and links. Preserve the existing `ASSESSMENT_DERIVED` / `ASSESSMENT_INFORMED` / `GENERAL_UPSTREAM` / `INSUFFICIENT` taxonomy; assessment-derived claims require pinned Index-first chronology. Read historical v1 records as explicitly `UNCLASSIFIED_LEGACY` instead of inventing causal attributions. Add validation and regression coverage without breaking the existing Upstream dashboard.

**Required `opensiro-contributions` PR provenance links (unreleased):** the reviewed human packet and prospective external PR disclosure must include validated links to the correctly parented contributions fork, product branch, exact implementation commit, actual fork-local review PR and pinned `.opensiro/` stable improvement record; missing or mismatched links block a **new** external PR. The AI disclosure must preserve independently verified assessment source/date/review SHA and not invent human review. A fork PR not yet authorized uses an explicit `NOT_CREATED` stage, and historical already-public PRs lacking a fork review disclose its absence without retroactive claims. Add a source-only structural validator and regressions; all external public edits still require their own consent. No SemVer bump or release is implied.

**Source-verified activity dashboard refresh (unreleased):** Add a six-hour/manual GitHub Actions pipeline that runs Upstream's native tests, reads fork-local metadata and original external PR/review states, and proposes date-stamped SVG/Markdown/provenance snapshots through a review-only PR. Unavailable or partial GitHub evidence fails closed; unchanged lifecycle facts produce no timestamp-only commit. This is secondary telemetry, not an automatic external-publication action or Organization outcome KPI.

**Upgrade metadata on demand (unreleased):** Once a real improvement is qualified and the specific fork write is authorized, a full-cycle `upstream upgrade` must initialize the verified fork's missing `opensiro/meta` from a pinned default-branch HEAD and create `.opensiro/state.json` plus its stable contribution record. A present branch is reused, an unknown or owner-`PAUSE/STOP` state blocks writes, and exact-SHA metadata plus aggregate readback is required before claiming a handoff ready for publication approval. An external PR already published is reconciled into that **one** intervention without posting again. Chat-only screening batches remain write-free. This is a prospective procedure, **not** a retroactive claim that missing historical metadata has been written.

**Single-harness Upgrade scope and fork-local PR review (unreleased):** The default `upstream upgrade` now **selects exactly one original harness** (or uses the explicitly named source) and stays there for all qualification attempts; it does not fall back to another repository after a failed hypothesis, missing meta branch or human CLA gate. A truthful source-local no-change/blocker is valid. End-to-end qualified work must prepare a human-visible **review PR in the matching `opensiro-contributions` fork**, with original-template PR title/body, exact code diff, native tests and current assessment-linked AI disclosure; the external PR is a separate later approval. Public fork-local proposal creation itself still needs exact current-conversation consent; without that, a read-only compare plus complete draft is the permitted handoff. The former historical v3 disclosure text claiming no per-PR approval is **not** copied into new publications. A concrete example needing a separately approved description correction is `browser-use/browser-harness#1034`. Batch screening remains chat-scoped, and no new SemVer/package/release or universal autonomous runner is claimed.

Compatible operating-rule changes accumulate here under review without an automatic SemVer bump for every PR. A coherent owner-approved bundle receives one final version/change package and one verified release, following [VERSIONING.md](VERSIONING.md).

## [0.16.0](changes/v0.16.0.md) — License/formalities-first admission, deferred human availability decisions

**Prospective MINOR, 2026-11-16.** Before contributor-popularity ranking, run the existing read-only source-pinned license, CLA/DCO and contributor-formality preflight. Distinguish screenable **read-only** research from unresolved rights/access and insufficient evidence, without auto-granting a license or claiming that GitHub access is cleared. New separate internal **Human gate — license, formalities & availability** issue form records only genuine deduplicated human decisions; chat batches still create no issues/PRs by default. [Protocol](PROTOCOL.md#license-and-formalities-first--human-gate-category).

## [0.15.0](changes/v0.15.0.md) — Popularity-first selection and chat-only batch reporting

**Prospective MINOR, 2026-11-16.** Default selections favor original harnesses with more unique GitHub contributors (stars only as a labeled fallback). Initial research coverage is breadth-first, then additional opportunities can receive a modest linear 1×–2× popularity preference or remain uniformly distributed on operator request; no contribution/PR quota. `upstream batch N` and `upstream upgrade batch N` produce **chat reports** without new per-batch issues, PRs, frozen manifests or schedulers. Reuse historical v0.8/v0.9 capability-first native testing, v0.11 fork handoff and independent CI receipts, respecting owner controls and exact external publication consent. [Protocol](PROTOCOL.md#default-popularity-priority--no-contribution-quota).

## [0.14.0](changes/v0.14.0.md) — Capability-first upstream upgrade

**Prospective MINOR, 2026-11-16.** `upstream upgrade` now selects demonstrable new harness user/operator capabilities, not frozen batches or bug-fix quotas. `upstream upgrade batch N` explicitly covers N distinct original repositories with S1/S2/S3/S3*/S4/S5 source-backed dispositions; native investigations concentrate on credible functional needs instead of six forced product experiments. `upstream batch [N]` remains a distinct technical/repair route. Historical Index-first chronology, live original PR readbacks, fork-local `PAUSE`/`STOP`, external communication consent and source-native benefit controls remain in force. [Procedure](PROTOCOL.md#capability-first-upstream-upgrade-new-work-not-historical-batching).

## [0.13.0](changes/v0.13.0.md) — Fork-local metadata and aggregate-only Upstream

**Prospective MINOR, 2026-11-15.** Approved source-of-truth switch: detailed per-harness attention, contribution records and attributable events live in `.opensiro/` on a verified target fork's separate `opensiro/meta` branch. Upstream aggregates rather than mirroring logs or requiring one issue per contribution. No mandatory maintenance TTL, and external PR status still comes from the original GitHub source. [Fork metadata](docs/FORK_METADATA.md) · [parallel legacy migration #2](https://github.com/opensiro/upstream/issues/2). Normative docs only; physical migration, validator and live observer remain unfinished.

## [0.12.0](changes/v0.12.0.md) — One improvement, one durable case

**Prospective MINOR, 2026-11-15.** A case-first operating workflow replaces frozen batch/revisit sequences as the normal unit of work. Research, implementation, external delivery and verified-outcome reporting remain source-linked and persistent across sessions. Working code belongs in the target-specific [opensiro-contributions](https://github.com/opensiro-contributions) fork; Organization [TODO.md](https://github.com/opensiro/vsm-oss-organization/blob/main/TODO.md) and S1–S5 authority remain in existing VSM OSS control. Source-native evidence, early working-fork verification and exact external-publication approval are retained. No new KPI or executor is created.

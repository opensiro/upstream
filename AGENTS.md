# Upstream AI entry

1. Follow canonical [START_HERE](https://github.com/opensiro/vsm-oss-organization/blob/main/START_HERE.md) → [ECOSYSTEM](https://github.com/opensiro/vsm-oss-organization/blob/main/docs/ECOSYSTEM.md) → the owning repository and **original source / verified fork-local metadata**, or minimal pre-fork issue.
2. Use the [v0.16.0 fork-local protocol](PROTOCOL.md). One harness may contain many improvements. Detailed operational state/events belong under `.opensiro/` on the verified fork's independent `opensiro/meta` branch; Upstream issues remain minimal pre-fork intake or coordination links, not a second event ledger. See [fork metadata](docs/FORK_METADATA.md). **Every newly created or reclassified contribution MUST be schema_version 2 with a verified `contribution_type`, `classification_rationale` and `classification_evidence`; run `python3 scripts/contribution_classification.py <path-to-contribution.json>` before the fork metadata write.** An Index assessment does not automatically make an intervention `ASSESSMENT_DERIVED`, and `UNCLASSIFIED_LEGACY` is read-only compatibility, not a new classification choice. Do not create batch/revisit iterations, a separate TODO queue or an independent VSM control plane.
3. If continuing predecessor work, read the actual [upstream-old](https://github.com/opensiro/upstream-old) issue/PR, its source pins and applied historical version. **Old #56 is upstream-old #56**, not new Upstream #56; old issue IDs are not automatically transferred.
4. For native implementation, check live fork parent, branch SHA, original license/CLA/PR policy and tool rights; code/tests belong in the matching [opensiro-contributions](https://github.com/opensiro-contributions) fork.
5. Before third-party outward public communication, show exact destination/action/content/diff and obtain explicit current-conversation owner approval. A general continuation instruction is **not** approval. [Consent gate](PROTOCOL.md#external-publication-consent).
6. At meaningful transitions, append an attributable fork-local event (or update minimal intake issue when no verified fork exists); re-read owner PAUSE/STOP before new effectful work, and report Organization **DONE / NOW / BLOCKED / NEXT / NEED YOU**. Shared current-work selection lives in Organization [TODO.md](https://github.com/opensiro/vsm-oss-organization/blob/main/TODO.md).
7. Do not invent an autonomous scheduler, S2–S5 closure, grader, fake merged PR, native test or unclaimed metric. The existing [Organization control plane](https://github.com/opensiro/vsm-oss-organization/blob/main/docs/CONTROL_PLANE.md) owns cross-domain authority.

**Capability-delta gate before Upgrade implementation:** Before coding any new feature, record a source-linked actor/task/output, original baseline and best workaround, a predeclared matched end-to-end observable result, VSM mechanism, honest unsupported guarantees and whether the user/agent capability materially changes. Report `MATERIAL_DELTA_SUPPORTED` / `DELTA_PENDING` / `NO_MATERIAL_DELTA` as chat/report dispositions only. Native test success, Index association, extra API options or narrower diagnostics alone do not establish new capability. Pending/negative candidates remain research or unqualified experiments, **not Upgrade PRs**. Continue within the *same* chosen harness. The `VSM derived & informed only` qualifier filters to canonical `ASSESSMENT_DERIVED` / `ASSESSMENT_INFORMED` with actual VSM linkage; it grants no causal reclassification. [Full gate](PROTOCOL.md#material-capability-delta-gate-before-implementation).

**Function-scoped Upgrade (explicit `S1`/`S2`/`S3`/`S3*`/`S4`/`S5` qualifier):** Before locking an unspecified original, run bounded **read-only function-first** source-native need screening and the usual per-source license/formalities preflight; prioritize a real, testable outcome over a missing Index label, popular fork or existing PR. Once selected, freeze **one original and the requested function scope** through all attempted hypotheses; do not widen to another function or source after failure. Record the decisive decision/feedback owner, legitimate right, inputs, enforcement separately, and return-to-operation closure. **For S5**, generic approvals, a policy file, permission prompt or static filter do not establish identity/ultimate-policy governance: a real owner decision, its return path and observable later-operation change are required. Test a positive user outcome, unauthorized/absent-owner negative and compatibility. `VSM derived & informed only` remains a filter over canonical origin classes; no new metadata enums, autonomy grade or authority grant. [Function-scoped procedure](PROTOCOL.md#function-scoped-upgrade--evidence-first-selection-and-closure).

**Competing-PR coverage is not established by existence or passing tests.** For every VSM-derived/informed Upgrade hypothesis, use [the function-ownership/overlap receipt](PROTOCOL.md#existing-work-functional-overlap-and-vsm-ownership-gate): pin historical assessment plus current original source and competing PR head/diff, identify the decisive VSM decision owner and closure, compare matched native cases, and explicitly assess the remaining user task. An S2 tab router, static limit, or health check is not S3; current-task retry or accumulated helpers is not S4. Evaluate continuation/dependent work before opening a duplicate, but never mutate another author's PR branch or post to an external repo without the separate exact public consent. A partial/uncertain overlap does not close the single-harness search; preserve `EVIDENCE_INSUFFICIENT` where functional proof is absent.

**Unspecified `upstream roadmap` / `upstream roadmap select` — Index-first discovery:** First use [scripts/roadmap_select.py](scripts/roadmap_select.py) to pin the accepted included Index cohort and produce source-native candidates; verify original repo/license/contributor formalities, issue bodies, competing PR heads, fork parent, owner PAUSE/STOP, live original head and prior roadmap before locking one original. `select` is read-only research leads only. Unnamed `upstream roadmap` continues from the first source-validated qualified original into the normal named full cycle, with no automatic publication. Missing grades and matching issue titles are not demonstrated C needs, and a ranking is not a scheduler or new contribution. [Selection protocol](PROTOCOL.md#index-first-upstream-roadmap-selection-unspecified-source-read-only-lead-screen) · [existing case view](scripts/roadmap_view.py).

**Mandatory accepted Index assessment gate:** Before **any named Upstream roadmap, upgrade, original-specific batch decision, code implementation or public fork/original publication**, read back an accepted `status: included` standalone general assessment and matching `data/catalog.psv` identity/`review_ref` for the exact original in a pinned `opensiro/vsm-harness-index` commit. Record accepted blob/Index SHAs, review date, Profile/Methodology and current original HEAD. A proposed PR, excluded record, predecessor vector or `.opensiro` draft does **not** qualify. If absent: `ASSESSMENT_REQUIRED / BLOCKED`; only lawful intake/source preflight and owning Index assessment/admission are allowed. Re-run roadmap after canonical Index admission and readback. See [mandatory protocol](PROTOCOL.md#mandatory-accepted-assessment-prerequisite--fail-closed).

**Architecture-first `upstream roadmap OWNER/REPO` — PLAN_ONLY full cycle to fork-local Issue:** Use one named original, current source/issue/PR heads and accepted historical Index assessment separately. Create a [Capability Roadmap Receipt](docs/CAPABILITY_ROADMAP.md), map actual VSM decision owner/closure and competing work before proposing useful composable `C` constructors. Optional `C(P)`/`A(P)` applies only when separately proved for S3/S4/S5; autonomy is never mandated. Offer source-native code, Profile/Skills specification feedback, or a separately permitted domain fork. VSM and cost-saving claims are hypotheses, not proof. **Default deliverable:** resolve or create the authorized matching fork, save the one Human/AI/receipt case on `opensiro/meta`, prepare the complete public fork GitHub Issue title/body, and publish/read it back **only after separate exact current-conversation owner approval**. Without consent, leave `READY_FOR_FORK_ISSUE_APPROVAL — NOT PUBLISHED`; without metadata rights, report `PERSISTENCE_BLOCKED / NOT_PERSISTED`. No automatic Index regrade, product PR or external-original Issue. The original maintainer template remains `DRAFT — NOT PUBLISHED` until another separately approved third-party action; code requires normal Upgrade and consent gates. [Route](PROTOCOL.md#architecture-first-upstream-roadmap-ownerrepo-plan-only) · [template](templates/EXTERNAL_ARCHITECTURE_ISSUE.md).

**Roadmap terminal decision obligation:** After one-pass source-native exhaustion, every named roadmap must select a present **GO / NO_GO / BLOCKED** operator decision in the Human, AI and receipt. `NEEDS_EVIDENCE` alone is not a decision or a request for another `continue`: choose present **NO_GO** for an unqualified feature hypothesis or **BLOCKED** only for precisely exhausted missing external/owner evidence. No manufactured source-native usefulness, fake `C`, unauthorized action or invented permission. Respect original/functional scope, source pin, existing work, native alternative, current PAUSE/STOP and exact public-consent gates. If PAUSE prevents a case rewrite, finish permitted read-only analysis but mark the new decision `PERSISTENCE_BLOCKED` until explicit RESUME. [Guide](docs/CAPABILITY_ROADMAP.md#mandatory-terminal-go--no_go--blocked-decision).


**Roadmap `.opensiro` persistence (named command default):** A named `upstream roadmap` request, including `зафиксируй`, `оформи`, `persist` or `до local issue`, requires an actual source-pinned `.opensiro/issues/<case-id>/` on a verified matching fork's independent `opensiro/meta`. Check parent, owner PAUSE/STOP, original rights, ID dedupe, permissions and any authorized missing-fork/meta provisioning; then read back exact metadata HEAD, cross-linked Human+AI, receipt and validator PASS. Do not substitute a chat ZIP or claim completion from planned paths. Without effective provisioning rights, report `PERSISTENCE_BLOCKED` rather than guess; preserve separate public Issue/PR approval and no plan-only `contributions/` records. Missing effective fork/meta write authority yields a chat-only fallback explicitly labeled `PERSISTENCE_BLOCKED / NOT_PERSISTED` — **not** a completed full cycle. A published public fork Issue is never inferred from a stored case.

**Stable roadmap case filenames:** Save `issue.md`, `constructor-sufficiency.md`, `roadmap.md` and `README.md` on the verified fork's `opensiro/meta`; never copy example `-v2` suffixes. Update links atomically, preserve Git history, owner PAUSE/STOP and schema-v2 semantics.

**Roadmap completion without interim approval loops:** `upstream roadmap` and "continue to the end" must finish all permitted source/issue/PR checks and deliver a verified fork-local Human + AI constructor case, source-pinned receipt, complete public fork Issue title/body and any justified original Issue draft together, when authorized; **no routine intermediate waits or user reviews**. A partial `NEEDS_EVIDENCE`, advisory re-assessment or absent verified fork is a finding to investigate, not an automatic stop. If no matching fork exists, provision one when separately authorized; otherwise deliver full research in chat but mark `PERSISTENCE_BLOCKED`, never invent fork links. If public fork Issue consent is absent, hand off its exact text and verified case without claiming an Issue exists. Stop only for a genuinely exhausted evidence blocker, a terminal no-change result, or a distinct action requiring exact present-conversation authority. This does not authorize implementation, fork creation or public publication. [Roadmap guide](docs/CAPABILITY_ROADMAP.md#one-pass-completion-and-user-attention).

**Capability-first `upstream upgrade` — one original harness, full engineering cycle:** if unspecified, run bounded eligibility/preselection and select **one** source. Lock the whole invocation to that original; after an unsuccessful capability hypothesis, test other source-backed possibilities **in the same harness**, never switch to another original. Do not request routine `continue`. Qualify need/mechanism/counterfactual/scope; when authorized implement on its matching `opensiro-contributions` product branch and independently run baseline/after, negative and native CI. Preserve `.opensiro/` only on `opensiro/meta`. Stage the exact source-template external PR title/body, AI disclosure and code diff **as a review PR inside the same `opensiro-contributions` fork**; show the real fork-local PR URL to the human after obtaining the separate current exact consent to create that public fork PR. Never merge fork PR to fork default branch. If that public stage is not yet approved, provide read-only compare/diff and complete draft, not a fictitious URL. External PR creation/editing requires **separate exact current-conversation consent**. A source-local CLA/maintenance, DORMANT/PAUSE/STOP, **unavailable authority to initialize missing meta**/runner, no valid functional improvement or exhausted safe hypotheses is a valid final blocker **for the selected source**: do not bypass it by changing harness. See [single-harness end-to-end Upgrade](PROTOCOL.md#end-to-end-single-source-upgrade--finish-at-human-pr-approval), [fork-local PR review and AI disclosure](docs/UPGRADE_PR_REVIEW.md). `upstream upgrade batch N` and `upstream batch [N]` remain distinct **chat-scoped multi-source screening** commands with no mandatory PR/public write.

**Required `.opensiro/` provisioning for full-cycle Upgrade:** after source-native qualification and an **independent verified effectful fork-write permission**, check the original-matching `opensiro-contributions/*` fork for `opensiro/meta`. If the ref is **confirmed missing**, initialize it from a pinned current fork default HEAD and commit `.opensiro/state.json` plus the **one stable intervention record** on that branch only; do not abandon a qualified, authorized source just because meta is missing. If the ref exists, re-read and reuse it; if unreadable, colliding, paused/stopped, unlicensed or unauthorized, fail closed **inside the selected original harness** and investigate only safe in-source alternatives; never switch harnesses. No implicit `ALLOW/ACTIVE`, owner `RESUME`, historical events, independent test results or original PR statuses. Read back the exact metadata HEAD and contribution and verify the fork with [`scripts/aggregate.py`](scripts/aggregate.py) before claiming `READY_FOR_HUMAN_PR_APPROVAL`. If an external PR is already live, reconcile its verified URL into **one existing/missing record** without creating another PR. This obligation applies to single-source `upstream upgrade`, **not** chat-only batches or read-only scans; never put `.opensiro/` in product branches. [Provisioning procedure](PROTOCOL.md#upgrade-metadata-materialization--missing-opensirometa).

**Issue decision watch (read-only unless separately enabled):** If an original issue (without original external PR) awaits a maintainer response, reuse the stable contribution in the verified fork `opensiro/meta` and its optional [source-linked `issue_watch`](docs/ISSUE_WATCHING.md). Verify original issue/comment source, owner control, and pinned baseline; do not switch whole-fork `ACTIVE` to `WATCHING`. Use `scripts/issue_watch.py` for on-demand source readback; `DECISION_CONFIRMED` is a human review signal, **not** external PR consent. The optional schedule is disabled until explicitly enabled and supplied its own cross-fork credential. Events/cursors only in the owning fork, with non-force CAS; no duplicate external PR and no source issue mutations.

**Formalities-first admission:** before any popularity ranking or prolonged new-source investigation, read original-source identity/SHA, actual license text/scope, contributor policy, CLA/DCO and access restrictions. Reuse [the old read-only preflight](https://github.com/opensiro/upstream-old/blob/main/docs/CANDIDATE_INTAKE_PREFLIGHT.md); it does NOT grant legal approval. Put only real unresolved owner questions in the separate [Human gate issue category](.github/ISSUE_TEMPLATE/human-gate.yml), reusing an issue with the same owner and exact decision scope; no per-batch or automatic per-row issues. Source/fork/provider availability is deferred for an explicit human decision. Do not change a paused fork, create derivatives or contact outside maintainers to resolve it. See [v0.16.0](PROTOCOL.md#license-and-formalities-first--human-gate-category).

**Mandatory Upgrade disclosure/links:** before preparing any new original-repository PR, use [the current review-gated AI form](docs/UPGRADE_PR_REVIEW.md) **as a requirement**, not a generic `AI assistance` paragraph. Include source-backed assessment path, pinned Index SHA, real `reviewed_at` and `review_ref` when verified, never falsely imply causal origin or human technical review. The **human handoff and proposed external PR body** must link the exact verified `opensiro-contributions/<fork>` repo, product branch, 40-character commit, actual fork-local review PR, and pinned `.opensiro/` contribution record; never link `opensiro-promotion` as the work owner. Run the [structural link checker](scripts/validate_upgrade_pr_links.py), independently verify live GitHub refs/PR body and source-native template and fail closed on missing/wrong-fork URLs. A fork-local draft may say `NOT_CREATED` until publicly approved; a new external PR may not, and historical already-open PRs must truthfully disclose an absent review PR. External body edits require exact current-conversation approval.

**Resumption / lost-context guard:** Never continue an approved-looking PR action from conversation memory alone. Re-read the one canonical fork-local schema v2 contribution, owner control, latest event, source/fork refs and real PR existence; generate the full five-link packet with [scripts/upgrade_handoff.py](scripts/upgrade_handoff.py), then run the [structural PR-body link checker](scripts/validate_upgrade_pr_links.py) with --stage preview/new on the **actual proposed public body**. A STOP after approval suspends publication until new exact consent; a generic AI disclosure or only a compare/commit URL is an explicit failure, not a completed handoff. Persist stop/next-action facts in that fork's metadata; do not duplicate a new Upstream ledger.

**Selection and chat reports:** for an unspecified source, prefer original projects with more unique public GitHub contributors (stars only as a disclosed fallback). Give each eligible source a first research turn, then apply modest linear 1×–2× rank priority for additional genuinely needed improvements; an explicit `uniform` request overrides. Historical OpenSiro contributions are distinct stable improvement IDs, **not** PR counts or a target quota. `upstream upgrade batch N` and `upstream batch N` are **chat-scoped reports only**: no new per-batch issues, PRs, frozen manifests, branches, events or independent task queue. Link source pins and existing `.opensiro/`; modify fork-local records only for a separately authorized substantive intervention. Reuse the historical v0.8/v0.9 native-research and v0.11 fork-native test/handoff work; don't build a universal runner as a default prerequisite. Read [v0.15.0 selection/reporting rules](PROTOCOL.md#default-popularity-priority--no-contribution-quota).

**SemVer and release cadence:** do **not** bump `VERSION`, add a numbered package or publish a tag/Release every time a protocol edit is approved. Accumulate reviewable changes under [Unreleased](CHANGELOG.md#unreleased), keep current `main` versus published Release distinctly reported, and seek explicit owner agreement on the **complete bundle** before a final numbered release PR/tag/Release. The [v0.16.0 consolidated candidate](docs/RELEASE_CANDIDATE_v0.16.0.md) is draft; the latest first-party published release observed at preparation was v0.13.0. Historical v0.14–v0.16 merged snapshots remain intact. A chat batch never causes a release or GitHub bookkeeping. [Release rules](VERSIONING.md#agreement-first-version-and-release-workflow).

**Conversational routes, not implemented CLI commands:** `upstream discover`, `upstream continue <issue URL>`, `upstream status`, `upstream batch [N]`, `upstream upgrade` and `upstream upgrade batch N`. If multiple current issues exist, an ambiguous `continue` is not a licence to select arbitrarily.

Actual root LICENSE Apache-2.0; existing source comments note a 2026-11-06 mitigation for the Docker **create** 409 race. No open first-party PRs or issues reported at intake.
- **Observed narrower gap for native test:** `ContainerManager._ensure` retries name conflicts across independent manager processes, but `_connect` starts an inspected `created` container without idempotence if a peer started it first. `_create` removes the just-created container on **any** startup exception, even when a peer independently started it between the original create and local start call. `DockerEngine.start_container` converts Docker API errors into `SandboxError`; Docker's already-started conflict/304 is not checked against final running state.
- **Risk and scope:** this is a plausible *interprocess start* race, not proof of a vulnerability, exploit, or affected deployment. The existing fake Docker client in `server/tests/sandbox/fake_docker.py` can deterministically inject a peer-start event at the source-native API boundary; no daemon or model required.

## Prespecified matched native observation

1. On exact pinned first-party code with **only a regression patch**, extend `server/tests/sandbox/test_lifecycle.py` with two parameterized fixtures for (a) the pre-existing `created` container path, (b) the local newly-created container path. Use the actual `FakeApi.start` interception to make the shared Docker state `running` as if another service process started it, then raise real `docker.errors.APIError(304)`. Exercise the first-party `DockerEngine` translation and `ContainerManager` through the existing `_touch` operation; assert no false user error and no removal.
2. **Expected BEFORE RED:** the two native variants raise `SandboxError`; in the locally-created case `_create` deletes the running container. Existing negative start-failure (500), foreign label and create-409 tests should remain meaningful controls.
3. Bounded possible fix: helper that calls native `start_container`; on any `SandboxError`, **only** accept the result if a fresh inspection of that **same container ID** now reports running. Otherwise re-raise original failure. Reuse in both `_connect` and `_create`, preserving cleanup when the container truly never starts.
4. **Expected AFTER GREEN:** same first-party native cases pass, no running container removed, prior 500 failure still removes incomplete container, foreign ownership still refused, existing 409 handling unchanged. Run the broader `tests/sandbox/test_lifecycle.py` offline suite, and report any dependency/version caveats.
5. Have **dev-alpha-2** (distinct deterministic SSH host) execute the pinned source-native Python tests and preserve command/session IDs, source/test/fix patch hashes, RED/GREEN output. No live Docker, agents, LLMs, providers, browser or external PR. On failure/null, hold the candidate without a benefit claim.

Current execution will use Python 3.12, a minimal isolated virtual environment with project native `pytest`, `docker`, `pydantic` and dependencies, and `--confcutdir=tests/sandbox` so unrelated PostgreSQL fixtures in the parent `conftest.py` are not loaded.

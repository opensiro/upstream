# Upstream contribution protocol — v0.14.0

[Home](README.md) · [Fork-local records](docs/FORK_METADATA.md) · [Architecture](docs/ARCHITECTURE.md) · [Historical migration #2](https://github.com/opensiro/upstream/issues/2)

**One harness may have many independent improvements. The detailed operational state belongs to its verified working fork, not a pile of permanent Upstream issues.** No fixed maintenance TTL is imposed. Upstream is an existing S1 domain of OpenSiro VSM OSS, not a second organizational control plane.

## Ownership and work unit

Before a real fork exists, Upstream may own one **minimal intake issue** containing a real source identity, open decision and evidence links; source-proven negative findings need no invented fork or patch. Once a correct [opensiro-contributions](https://github.com/opensiro-contributions) fork is verified, use `.opensiro/` on its independent `opensiro/meta` branch as the **canonical local state and attributed decision/event history** for all that harness's contributions. One `contributions/<stable-id>.json` = one independently scoped useful improvement/repair, not an issue, chat session, old batch, external PR or mandatory new issue. An Upstream issue may remain as a link/operator task, never an authoritative duplicate mutable ledger.

Read [docs/FORK_METADATA.md](docs/FORK_METADATA.md) for the initial JSON contract and authority/branch rules. The original GitHub repository alone owns the actual external PR's open/merge/closure/reviews. Upstream only shows source-linked dated projections.

## Research and qualification

1. Verify original repository identity and exact source revision, license, contributor rules, existing behavior, competing PRs, and prior source links including [upstream-old](https://github.com/opensiro/upstream-old).
2. Ask **who needs what NEW task/output and why**, or which existing behavior is demonstrably broken. Propose a bounded benefit proxy and original alternative. A retry fix remains a repair unless a new feature is independently supported.
3. Respect provenance order: `ASSESSMENT_DERIVED` requires an earlier dated and pinned Index-first prediction; `ASSESSMENT_INFORMED`, `GENERAL_UPSTREAM` and `INSUFFICIENT` must not be misrepresented as causal VSM improvements.
4. Check native **need, mechanism, counterfactual and scope**. Unsupported claims remain pending. No mandatory six-function S1–S5 scan or per-session batch.

## Capability-first `upstream upgrade` (new work, not historical batching)

These are **conversational operator routes**, not shell commands, a new scheduler, a frozen-batch producer, or automatic authority to write to forks. Their purpose is to find a **real new user/operator task or decision** that an agent harness cannot currently perform, explain why a VSM mechanism is a useful hypothesis for that need, and then independently test the smallest native improvement. Use the current [fork-local metadata](docs/FORK_METADATA.md) and [read-only aggregator](scripts/aggregate.py); the original repository and Index remain the respective product/assessment sources of truth.

| Invocation | Selection and result |
| --- | --- |
| `upstream upgrade` | Select the most promising **one** source-backed functional opportunity from current intake, existing verified forks, open maintainers' needs and previously blocked improvements; investigate deeply. Do not open a new batch. |
| `upstream upgrade OWNER/REPO` or `upstream upgrade <contribution-id>` | Resume/re-evaluate a particular original source or stable fork-local improvement after verifying identity, current state, source revision and applicable authority. A source can have many distinct improvements. |
| `upstream upgrade batch N` | **Explicit legacy-compatible breadth mode:** select **N distinct original harnesses** (e.g. 10), not N PRs, fixes, repeated sessions or guaranteed accepted features. For each harness make a source-backed **S1/S2/S3/S3*/S4/S5 disposition** (supported / disproved / not applicable / pending, with an actual reason) to avoid S2-only selection. Deep native tests target the strongest plausible capability rather than mechanically executing six unrelated experiments per harness. If fewer than N eligible sources exist, report the exact shortfall; never pad or duplicate. No new frozen cohort or per-batch issue. |
| `upstream batch [N]` | **Separate technical-screening route**, not an alias for `upgrade`; source-backed repairs may be its main outcome. Use current source and authority. Historical `upstream-old` batch files remain immutable evidence, not automatically current instructions. |

### Upgrade decision sequence — one improvement, not one PR

1. **Read and select, without writing:** establish today's Organization selection and active operator instruction; inspect the [Upstream aggregate](scripts/aggregate.py) with explicit coverage warnings, exact original GitHub issue/PR statuses, old evidence and deduplicated `.opensiro/` IDs. `DELIVERED`, `MERGED`, `CLOSED_UNMERGED` and `BLOCKED` are separate facts; an old merged fix is not a new capability to re-propose. Missing metadata is `UNKNOWN`, not evidence of no opportunities. Prefer credible unmet operator/maintainer demand, source-native reachability and testability over filling a quota or chasing low assessment grades.
2. **Name the new task before prolonged code exploration:** give a concrete **actor → trigger → new action/decision → observable output/API**, the closest existing original-version workflow or alternative, and a bounded benefit proxy (task possible, correct evidence discrimination, reduced decision latency/cost, etc.). A missing API, low VSM grade, failure-injection mock or empty slot in a six-function table is not proof of need. A pure bug fix, retry/locking regression, dependency upgrade or refactor is `REPAIR_ONLY` unless an independently evidenced new user task is delivered. Valid repairs remain useful but report them separately from upgrade's feature findings.
3. **Link the VSM hypothesis without causal laundering:** use the relevant S1/S2/S3/S3*/S4/S5 mechanism(s), decisive runtime owner, feedback/control boundary and original source evidence. Consider all plausible functions, not S2 by default; do **not** require six product hypotheses or grade changes. `ASSESSMENT_DERIVED` requires a **pre-existing dated, pinned Index-first specific prediction** before fresh original-source study. For issue/source-first needs use `ASSESSMENT_INFORMED` or `GENERAL_UPSTREAM`; mark insufficient chronology as `INSUFFICIENT`. Never re-label a historical source-first result as Index-derived after the fact.
4. **Qualify or falsify one bounded opportunity:** pin original code/issue and current supported workflow, test native baseline and smallest counterfactual, compare proposed new output under matched fixtures, and include a negative/compatibility control. Resolve source-native **need / mechanism / counterfactual / scope** as explicit `PASS` or `PENDING` with evidence. A passing test of existing behavior alone, a mocked impossible exception, a signature-only test, or passing CI without the new user output does not establish benefit. If a real agent/model outcome cannot be tested in the permitted environment, state that limit; do not claim task-quality gains from script tests.
5. **Only after admission, check effectful authority:** original license, CLA/DCO, contributor policy, exact fork parent, current branch HEAD, `owner_control`, attention state, work collision and explicit grant. **`PAUSE` or `STOP` blocks new effectful steps; `DORMANT` is not automatic consent to resume engineering.** A request to review or run `upstream upgrade` is not itself a fork-local owner `RESUME`. Read-only investigation and an exact proposed next decision may continue; do not mutate metadata or product branches while blocked.
6. **Implement only a demonstrated need:** prepare real source-native code/tests on an allowed fork product branch, independent before/after verification and a precise diff; place OpenSiro-only records/events **only** on the fork's `opensiro/meta` branch. Update one existing stable contribution record per independently useful intervention; one intervention may link multiple original/replacement PRs. Do not add an Upstream issue, PR, permanent process, manifest or fork merely for recordkeeping.
7. **Deliver or stop accurately:** before every outward third-party issue/comment/PR/review or public fork-local proposal use [exact current-conversation consent](#external-publication-consent), including destination and final content/diff. Independently re-read any original PR state; `OPEN` / `MERGED` / `CLOSED_UNMERGED` / `UNKNOWN` never establish deployment or usefulness by themselves. A duplicate, unproven need, required maintainer decision, permission blocker or well-supported no-change is a legitimate final disposition; **no patch/PR quota**.

**Operator output per source:** original URL + source SHA; existing fork/meta SHA or `UNMAPPED`; existing contribution IDs and external PR readback; actor/task/output, baseline/alternative, VSM mechanism and origin classification; bounded benefit proxy and decisive native result; four admission gates; `FEATURE_QUALIFIED`, `OPPORTUNITY_PENDING`, `REPAIR_ONLY`, `CLOSED_NO_CHANGE` or `BLOCKED` **as narrative dispositions, not invented JSON work states**; smallest next action and its decision owner. For `batch N`, report **N distinct selected sources (or explicit shortfall)**, six per-source function dispositions, feature vs repair counts, and independently verified contributions/PRs separately. Report `SCREENING_COMPLETE` separately from `OPPORTUNITY_DECIDED`; never declare all six product capabilities researched merely because six checkboxes exist.

## Implement and validate

Inspect original source, actual fork `parent.full_name`, default branch, license/CLA/DCO, branch SHA, contributor rights and overlapping PRs before source changes. The fork has **separate work branches for product code and `opensiro/meta` for OpenSiro-only evidence and events**; never include `.opensiro/` in the original project's PR diff. Don't edit upstream README or CI for OpenSiro metadata. The metadata branch itself must be protected against lost updates through optimistic HEAD checks and one-writer-per-fork coordination.

Demonstrate feature behavior in the original native stack with source-pinned baseline/after evidence and appropriate negative/compatibility control; for a repair, reproduce a real reachable original failure. Record exact fork/source SHA, test commands, result and limitations as links; large raw logs stay in their original technical owner, never copied to Upstream. If a fork cannot be verified, preserve a minimal blocker at intake; do not pretend a branch or passing CI exists.

## Deliver, observe, choose attention

Use the original PR template, policy and AI disclosure. Before outreach follow [External-publication consent](#external-publication-consent). A specific original/replacement PR chain maps to the **same contribution ID**. Source-owned external status is one of `OPEN`, `MERGED`, `CLOSED_UNMERGED`, `UNKNOWN`, with separate draft/review/CI qualifiers. Never interpret closed-unmerged as disproved usefulness or merged as measured deployed benefit.

Maintain the independent fork **attention** setting `ACTIVE`, `WATCHING`, `DORMANT`, `ARCHIVED`. These are elective, reversible choices about whether to perform engineering or scheduled observation; not a maintenance commitment or TTL. State/decision changes and human `PAUSE`, `STOP`, `RESUME` are attributed **significant** events in the fork metadata. A cooperating executor must re-read owner control and effective authority before every new effectful step. Writing STOP does not cancel already-running processes.

At meaningful transitions report existing Organization **DONE / NOW / BLOCKED / NEXT / NEED YOU**. The owner controls cross-repository selection from [Organization TODO.md](https://github.com/opensiro/vsm-oss-organization/blob/main/TODO.md). Upstream is a **rebuildable aggregate** from fork metadata at verified SHA and current first-party external PR reads, not another event store, task scheduler or second VSM. When no data or live readback is available, report **UNKNOWN**, not success/zero.

## External-publication consent

The [historical effective restriction](https://github.com/opensiro/upstream-old/blob/main/docs/EXTERNAL_PUBLIC_COMMUNICATION_GATE.md) still applies: **before every public third-party issue/comment/reply/PR/review/design question or public fork-local proposal**, present exact destination, specific action, final public text and verified code diff as applicable and obtain explicit current-conversation consent. Significant content or destination changes need renewed consent. General permission to continue, internal documentation approval, a metadata event or passing tests is not consent.

Internal OpenSiro research/doc/issues/PRs and independently authorized working branch preparation follow their own grants. Third-party external actions also require legal/CLA/DCO/provider permissions and actual executor rights. Record missing permission as blocked; do not post.

## Migration and metrics

The predecessor protocol through v0.11.0 and frozen original historical sources live in [upstream-old](https://github.com/opensiro/upstream-old). v0.12.0 case-first Upstream issues remain valid historical coordination records; **v0.13.0 moves detailed ownership to fork-local metadata**, and [migration #2](https://github.com/opensiro/upstream/issues/2) covers reviewed per-fork parallel extraction and status progress. Do not rewrite historical evidence or assume a fork exists.

The current Organization `verified_external_outcomes` accepted-merge export remains **unclaimed** for the new source until separate verified semantic/collector cutover. PR state is descriptive public telemetry, not a proof of independent usefulness. Protocol SemVer is not a deployment or autonomy grade.

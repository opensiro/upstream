## 1. ucode

- **Assessment:** [assessments/uc/ucode.md](https://github.com/opensiro/vsm-harness-index/blob/85ae995fc2551ac0a076609bce0300d075cac2d5/assessments/uc/ucode.md), reviewed 2026-10-24, source `sppideey/ucode-agent@be41840d1219ea45490ac8c61ba84fa48d3119a6`.
- **Observed S2 mechanism:** Three independent worker tool loops share a process-global Promise-chain FILE_WRITES/command mutex.
- **Falsifiable possible weakness:** If a holder's native write/command action rejects, the stored Promise tail may remain rejected; a later worker could fail to enter its guarded write, causing liveness failure without any real conflict.
- **Expected product-native benefit if true:** Preserve queue liveness after failed/cancelled holders, still serializing two legitimate overlapping writes.
- **Null/falsifier:** Every lock continuation catches/absorbs prior rejections before appending, or errors are handled such that later workers are already admitted in supported mode.

## 2. OwnPilot

- **Assessment:** [assessments/ow/ownpilot.md](https://github.com/opensiro/vsm-harness-index/blob/85ae995fc2551ac0a076609bce0300d075cac2d5/assessments/ow/ownpilot.md), reviewed 2026-10-24, source `ownpilot/OwnPilot@eb4c27f29d4d12778621a83e49cd673cd8b62239`.
- **Observed S2 mechanism:** Child Docker isolation and single-winner crew queue task claim using SKIP LOCKED protect independent agent work.
- **Falsifiable possible weakness:** A failed claimant may still update claimed_by while another won a transaction, or a cancelled worker might retain a task claim without a requeue path.
- **Expected product-native benefit if true:** Ensure claim ownership is atomic and eligible tasks recover after true worker failure while protecting running claims.
- **Null/falsifier:** Current row-lock and lease/recovery logic handles failed claims and abandoned owners, or automatic reclamation is outside supported first-party contract.

## 3. CodeWhip

- **Assessment:** [assessments/co/codewhip.md](https://github.com/opensiro/vsm-harness-index/blob/85ae995fc2551ac0a076609bce0300d075cac2d5/assessments/co/codewhip.md), reviewed 2026-10-24, source `hasitpbhatt/codewhip@be51da68db85096e9fa0455777e3ed89985df756`.
- **Observed S2 mechanism:** delegate_many allocates fixed child token shares and reserves a coordination share for the parent from a finite token budget.
- **Falsifiable possible weakness:** If available parent budget is less than active child count, integer rounding may allocate zero or overallocate child budgets, bypassing the promised parent reserve or causing runaway children.
- **Expected product-native benefit if true:** Validate bounded nonzero child quotas and preserve the declared parent reserve without changing normal fair fan-out.
- **Null/falsifier:** Allocator already handles tiny budgets, rejects unsupported budgets, or zero-child quota safely stops child work before any model call.

## 4. Phone Harness

- **Assessment:** [assessments/ph/phone-harness.md](https://github.com/opensiro/vsm-harness-index/blob/85ae995fc2551ac0a076609bce0300d075cac2d5/assessments/ph/phone-harness.md), reviewed 2026-10-24, source `ShawnPana/phone-harness@a80f8845e125269545bbf462967fe7b620691422`.
- **Observed S2 mechanism:** A plugin-process threading.Lock guards entire phone_exec child-script transactions against distinct subagent collisions.
- **Falsifiable possible weakness:** If the script spawn fails after lock acquisition, a missing finally/release may indefinitely leave the phone busy for subsequent subagents.
- **Expected product-native benefit if true:** Guarantee native release and clear busy feedback on all supported script-launch/timeout exceptions.
- **Null/falsifier:** The handler uses a context manager or try/finally, or child-subprocess failures never bypass lock release.

## 5. yottacode

- **Assessment:** [assessments/yo/yottacode.md](https://github.com/opensiro/vsm-harness-index/blob/85ae995fc2551ac0a076609bce0300d075cac2d5/assessments/yo/yottacode.md), reviewed 2026-10-23, source `yottadynamics/yottacode@11ffd5884a2827636d54b14c0d60d53c9c93c5d8`.
- **Observed S2 mechanism:** Opt-in dispatch validates declared file partitions, currently running claims and isolated child worktrees before accepting concurrent writers.
- **Falsifiable possible weakness:** Two lexical path aliases for the same in-repo file may pass partition disjointness checks and be assigned to different dispatch children.

- **Null/falsifier:** First-party validateWritePartition normalizes all supported aliases and checks running tasks, or the candidate path forms are explicitly disallowed.

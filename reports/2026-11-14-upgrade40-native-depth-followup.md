### Akmatori: evidence is usage, not confirmation

First-party `memory_uses` stores `run_id`, `incident_uuid` and `kind` ([source](https://github.com/akmatori/akmatori/blob/be62d926fe6d92dceb5cf12e9a95cb587433cdf1/internal/services/memory_usage.go)); citing the same memory three times changes `use_count` three times. This is a usage/recall metric, **not** three independently observed explanations. `ApplyAgentMemoryEvidence` separately rejects agent-written `confirmed` and downgrades causal claims ([source](https://github.com/akmatori/akmatori/blob/be62d926fe6d92dceb5cf12e9a95cb587433cdf1/internal/services/memory_evidence.go)). Both behaviors were confirmed through tests or source, not proposed as defects.

[Maintainer issue #67](https://github.com/akmatori/akmatori/issues/67) explicitly leaves cross-incident corroboration and outcome-based automatic verification open for a later rule/action log/operator thumbs-up. **Current fit:** `need=PASS; mechanism=PASS; counterfactual=PENDING; scope=PENDING`. Minimal next check: two truly independent extractor outputs of the same claim and a contradictory third incident, each with provenance and separate negative control; agree on whether the user receives a *corroboration hint* instead of grade promotion. Do not infer an automatic trust threshold from `memory_uses`.

### Slack reviewer: distinguish a conditional boundary from a real defect

The workflow loads a GitHub diff and then checks the expected HEAD SHA; at publish time it checks HEAD again and requires successful required checks before an `APPROVE`. The extracted exact Python payload accepts a synthetic incomplete diff while `changed_files=2` because no file-inventory check exists. **A constructed HTTP-200 partial diff is an injected hypothetical**, not a recorded GitHub response. Public GitHub diff limits (including the 300-file limit) can instead cause an HTTP error; `gh api` failure stops the workflow rather than passing to the model. Do not turn the synthetic test into a confirmed production review failure.

**Fit:** `need=PENDING; mechanism=PASS; counterfactual=PENDING; scope=PENDING`. The next native falsifier is an actual first-party GitHub PR where the diff endpoint returns a successful response with fewer paths than the PR metadata/file inventory, or an independently sourced product requirement to enforce content completeness even for synthetically incomplete input. Only then assess a fail-closed file inventory check and realistic renames/binaries/submodules.

**Go-agent critical distinction:** two client requests after a post-side-effect store error are *not* the same as an internally retried single tool call; the harness emits an error and waits for the embedding client to retry. Idempotency for side-effecting external APIs may require a **caller-supplied durable key and transactional business owner**, not only a new session-level flag. The test is a reproducible **conditional failure case** and supports asking for a product contract, not automatically changing SDK behavior.

**WittyCode critical distinction:** the canonical target path is already displayed in the Python action-view model; the GUI surface and Windows junction/reparse semantics were not independently validated. The Linux-only failure in the unfiltered suite must not be mislabeled a Windows regression.

**Sapper critical distinction:** `sapper confirm` concerns *intent* confirmation, while `sapper fact` records observations. A structural graph validator and a source-integrity verifier are different APIs. If users need independently signed fact provenance, require a maintainer use case first.

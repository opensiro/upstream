## 2. CAO — requested workflow-step replay is already integrated; ACP host is a genuine separate feature

Its PR explicitly defers fingerprint-reuse, derived run write-back and script-tier replay; do not claim those have shipped. **`CLOSED_NO_CHANGE` for a duplicate YAML-tier single-step-replay proposal**, while distinct deferred capabilities remain independently unadmitted. The PR is original-source work, not OpenSiro-authored delivery.

**Separate source-first new actor/task from first-party [CAO #649](https://github.com/awslabs/cli-agent-orchestrator/issues/649):** an ACP-capable IDE/host starts one CAO session and sends/receives typed turns, including truthful status/permission/stream capability negotiation; current CAO alternatives are HTTP/MCP request-response and AG-UI metadata stream, not a host-facing ACP agent. The checked `src/cli_agent_orchestrator` tree contains **no current host-facing ACP server** (provider-side Kiro ACP references do *not* supply that feature). The original issue and its first-party discussion identify real consumer integration but also a critical undecided **trust boundary**: unauthenticated proxy access to other sessions and arbitrary `mcpServers` command passthrough must not be admitted by inference. A reviewer confirms direction while requiring a trust model, scoped profile binding, honest limited streaming and source-native conformance checks. New `SOURCE_FIRST` prospective `MAJOR_FEATURE` / **`BLOCKED_EVIDENCE`** until the maintainer chooses the restricted Phase 1 host/proxy authority contract.
